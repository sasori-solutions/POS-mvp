# Account flow verification

`npm run test:e2e` starts a dedicated Vite server on port 5174 and runs the account flow at desktop and phone widths. Google identity and the account API are intercepted only inside Playwright; every tab refuses requests to non-loopback hosts. These tests cover creation response loss, PIN validation/lockout, reload and multi-tab lock/logout, immediate closure while revocation is delayed, cancelled OAuth callback cleanup, a fresh sign-in while another tab remains logged out, repeated logout of an already-revoked session, rejected authentication logout warnings, and exclusion of Google provider tokens from saved sessions. The shipped application has no fixture login or password authentication UI. These tests establish frontend transitions and storage behavior; they do not establish live Google consent behavior. Synthetic screenshots are saved in `/tmp/pos-mexico-{desktop|mobile}-{login|business|pin|ready}.png`.

The Vitest integration suite creates synthetic password identities only in a **loopback local Supabase instance**, signs them in through real Supabase Auth, and calls the deployed local account function against Postgres. It tests tenant isolation, restricted tables/RPCs, atomic concurrent creation/retries, token revocation/expiry, actual SDK classification of duplicate Auth logout, concurrent server PIN lockout/cooldown recovery, forbidden-origin POST denial, and body size limits. It deletes its synthetic identities and business rows afterward. Local Supabase's gateway can add wildcard CORS headers and accept preflights; the account handler still denies authenticated POSTs from forbidden origins.

Start Docker, run `npm run db:start`, and serve `account` with `npm run api:serve`. The local `.env.functions` must contain `ALLOW_TEST_PASSWORD_AUTH=true`; this setting is forbidden for cloud deployments. Run `npm run test` after those services are ready. The integration suite reads local credentials from `supabase status -o json` without printing them, and skips when no local instance is running. Skipped integration tests are not security verification.

To supply a local instance explicitly, set `TEST_SUPABASE_URL`, `TEST_SUPABASE_ANON_KEY`, and `TEST_SUPABASE_SERVICE_ROLE_KEY`. Tests refuse non-loopback URLs. `TEST_LOCAL_DB_CONTAINER` can identify a differently named local database container.

Real Google OAuth must also be checked manually on an allowlisted app URL after the Google provider is configured. Use an authorized pilot account; do not put credentials or real merchant data in fixtures or automated test screenshots.

After a production upload, `npm run check:live -- https://pos-mexico-mvp.pages.dev` verifies direct SPA routes and every generated asset against `dist` using anonymous GETs. It does not authenticate or replace the real Google/PIN flow.
